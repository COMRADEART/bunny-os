# Security patch operations

Kernel, browser, Bunny, broker, installer, Flatpak runtime, local-model runtime, plugin-publisher, and application-catalogue vulnerabilities follow: restricted triage → severity/embargo owner → minimal patch → reproducible build → focused regression/security/privacy/accessibility tests → new immutable candidate → protected approvals → signed emergency release → user notice/revocation → post-release verification.

Compromised keys/publishers are revoked before new content is accepted. An emergency never bypasses signature, rollback, recovery, license, provenance, or two-person release approval. If safe repair is not ready, disable or revoke the affected optional component; do not publish an unverified replacement.
