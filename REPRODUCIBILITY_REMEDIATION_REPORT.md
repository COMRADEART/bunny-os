## Nine defects found by running the tooling

Each was invisible by reading. This is the same pattern the hosted builder
produced five of, and it is recorded in the same form.

| # | Where | What happened |
| --- | --- | --- |
| R1 | `mirror-base-image.sh` | skopeo refuses `name:tag@sha256:…` — *"Docker references with both a tag and digest are currently not supported"* — which is exactly the form this project pins. The tag is stripped for the registry call and kept in the lock, because rewriting the recorded reference would make the evidence disagree with itself. |
| R2 | `build-builder-image.sh` | podman refuses `--timestamp` beside a `SOURCE_DATE_EPOCH` build argument: *"timestamp and source-date-epoch would be ambiguous if allowed together"*. |
| R3 | `record-toolchain.sh` | `crun --version` put the number in a different field than assumed, so the lock recorded `crun` as version **`version`**; `createrepo_c` recorded as **`)`**. Both would have compared *equal* between two builders and satisfied the toolchain check while establishing nothing. `write-builder-lock.py` now refuses a version that is not version-shaped. |
| R4 | `resolve-package-lock.py` | dnf5 rejects `--downloadonly` before the subcommand, and rejects `--destdir` on `install` at all; dnf4 accepted both. The transaction is taken from the libdnf5 cache instead. |
| R5 | `resolve-package-lock.py` | The repository id was joined to the filename with `%%`; `rpm -qp` read that as a format escape, collapsed it to `%`, and could not open the file it had just been given. |
| R6 | `resolve-package-lock.py` | **Fedora signs `RSAHEADER`, not `SIGPGP`.** Querying `SIGPGP` reported all 474 packages as `unsigned`. A supply-chain lock recording every Fedora package as unsigned is both false and wrong in the dangerous direction. |
| R7 | `install-packages.py` | The clock override was applied to the `rpm --query` calls either side of the transaction, which is **wider than the lock declares**. rpm exited 1 and `check=True` reported only an argument list. Scoped to the dnf process; the failure now names itself. |
| R8 | `install-packages.py` | libfaketime rejects a bare Unix timestamp — *"failed to parse FAKETIME timestamp"*. It wants a formatted absolute date, rendered in UTC so two builders in different time zones freeze to the same instant. |
| R9 | `install-packages.py` | The snapshot repository had `gpgcheck=1` and no key, so dnf refused the whole transaction: *"The repository does not have any OpenPGP keys configured."* **This was the check working.** The fix points it at Fedora's own keys; `gpgcheck=0` and re-signing with the development key were both available and both wrong. |

R3, R6 and R7 are the ones that matter beyond their immediate fix. Each would
have produced a lock or a build that *looked* correct: two garbage version
strings that compare equal, a signature field that reads "unsigned" for
everything, and a clock override wider than the document declaring it.

## What is blocked, and by what

**The hosted half cannot run.** Workstreams 25, 27, 28 and 29 need both builders
to pull the retained base, the pinned builder image and the package snapshot. The
retention channel chosen for this pass is `ghcr.io`, and the available GitHub
token carries `gist, read:org, repo, workflow` — no `write:packages`. Nothing was
pushed, and the retained inputs currently exist only on the local builder, which
is the same defect this remediation exists to remove.

That is one credential, not a design problem:

```text
gh auth refresh -h github.com -s write:packages,read:packages
```

Until then `local-hermetic-repeatability` is the only measurement available, and
a local-only result establishes determinism rather than reproducibility.

## SELinux: two subchecks, one composite

`selinuxLabels` stays as dimension six of seventeen and becomes a composite over
two subchecks owned by two stages:

```text
intendedSelinuxContexts   archive stage           collectable now
appliedSelinuxContexts    installed-system stage  needs a booted installed system
```

The composite is `MATCH` only when every subcheck **required at the current
stage** is `MATCH`, and a subcheck owned by a later stage is reported as
outstanding and never counted as satisfied. An archive comparison can therefore
reach `REPRODUCIBLE` while `satisfiesInstalledSystemSelinux` stays `false`, and
the report says both. Total evidence required is unchanged; what changed is that
the archive-observable half is now collected instead of the whole dimension being
`NOT_COLLECTED` for a reason no archive build could ever fix.

## What this does not establish

* That any of the fifteen files now match. No two-builder comparison has been run
  against the remediated build.
* That the builders are independent. The toolchain model and gate exist; no pair
  has been evaluated through them.
* That the base is retained anywhere an independent party can reach.
* Anything about installation, recovery media, hardware, encryption, update,
  rollback or secure boot. An archive-only build qualifies none of them, and both
  protected gates still refuse such an artifact by name.

## Addendum, 2026-07-30 — the measurement was made, and it changed the diagnosis

This report closed with *"whether they work is a two-builder measurement that has
not been made."* It was made. Three of the mechanisms did not do what this report
described, and each was invisible by reading:

| Mechanism as described here | What it actually did |
| --- | --- |
| "the transaction runs under a frozen clock" | it ran under a clock that *started* at the epoch and then advanced. `FAKETIME` carried an `@` prefix, which is libfaketime's start-at mode, not its freeze mode. `INSTALLTIME` spanned epoch+4 to epoch+18 and fifty of 1,015 packages fell on a different second between two builds. |
| "the transaction" | there were two. The `dnf remove` minimisation ran with no override at all, and libdnf5 wrote a live wall clock into its transaction history: 1785439455 against 1785439658. |
| — | `usr/share/bunny-os/finalisation.json` had identical content and mtimes 203 seconds apart. Layer tars carry entry mtimes and no dimension compared them, so the archive difference had no file to attribute it to. |

Two more defects were found in the evidence apparatus rather than the build:

* **The input locks were not in the commit.** All four were untracked and had been
  hand-copied into each "fresh clone". A hosted builder has nothing but the
  commit, so the pins pinned nothing a second builder could see.
* **Both builds shared a container store and a layer cache.** The driver created a
  store per build and never told podman about it. podman keys its cache on the
  instruction and the context digest, so the second build could have been served
  the first one's layers wholesale — a comparison that can only pass.

The full diagnosis is in `docs/SQLITE_DETERMINISM_BASELINE.md` and
`RPM_DATABASE_DETERMINISM_REPORT.md`. The general point is the one worth
carrying: this report was accurate about what was *implemented* and every claim
in it about what that implementation *does* was a claim nobody had checked.
