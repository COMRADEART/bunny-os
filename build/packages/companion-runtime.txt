# Companion runtime: local AI inference and offline speech I/O.
#
# These are the binaries the companion's adapters and voice/speech runtimes
# resolve at runtime:
#
#   llama-cpp                   /usr/bin/llama-cli  — local text generation
#                                                  (the local.llamacli adapter)
#   [libvosk.so]                /usr/lib64/libvosk.so — offline speech
#                                                  recognition (ctypes, no pip);
#                                                  installed as vosk-api-devel,
#                                                  already declared in
#                                                  desktop.txt — Fedora 44 ships
#                                                  no bare vosk-api package
#   espeak-ng                   /usr/bin/espeak-ng  — offline speech synthesis
#   speech-dispatcher           /usr/bin/spd-say    — the TTS broker the voice
#                                                  runtime speaks through
#   speech-dispatcher-espeak-ng the espeak-ng output module speech-dispatcher
#                                                  loads
#
# None of them auto-download a model. The trusted model directories
# /usr/share/bunny-os/agent-models and /usr/share/bunny-os/speech-models are
# provisioned by the operator (or by a future vendored-model install route),
# and a missing model is reported unavailable by the adapter rather than
# fetched — offline by construction, no world-writable model file.
#
# Package names verified against packages.fedoraproject.org and against the
# Fedora 44 repositories at build time: llama-cpp, espeak-ng, speech-dispatcher
# and speech-dispatcher-espeak-ng resolve as named, and the fc44 repos carry
# vosk-api-devel only — a build listing bare `vosk-api` fails dnf with "No
# match for argument", which is how this file first met that fact.
llama-cpp
espeak-ng
speech-dispatcher
speech-dispatcher-espeak-ng
