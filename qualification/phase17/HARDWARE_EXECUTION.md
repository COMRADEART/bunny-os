# Hardware execution

Hardware submissions retain operator pseudonym, `HW-NNN`, machine and medium
identity, independently observed artifact digest, CPU/RAM/GPU/storage/firmware,
Secure Boot, network/audio/microphone facts, companion modes, journeys, and
per-dimension outcomes. `PASS` requires an evidence reference. A boot is one
dimension, not `HARDWARE_PASS`. Native 3D failure is not converted into
`NOT_SUPPORTED`; fallback success stays a separate fact. Contradictory machines
are preserved without averaging. Any support claim requires an explicit,
standing hardware-owner policy and remains bounded to that policy's scope.
