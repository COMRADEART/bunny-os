## The record model

Every requirement carries: id, category, description, evidence type, evidence
reference, generated time, source commit, result, reviewer, optional expiry,
waiver status and blocker status.

Four ways a record can lie are checked rather than trusted:

| Failure | Check |
|---|---|
| **Forgery** | the record carries the artifact's SHA-256; the gate recomputes it. A record naming a missing file, a changed file, or no digest at all blocks. |
| **Staleness** | a record past `expiresAt` blocks, whatever its result. |
| **Wrong commit** | a record generated from a different commit than the candidate blocks. Evidence does not transfer between commits. |
| **Self-review** | a `third-party-report` or `physical-hardware-report` from a reviewer not registered as independent blocks. |

`UNKNOWN`, `NOT_RUN` and `BLOCKED` all block, as does a category with no record.
There is no code path that treats absence as success.

**Waivers are recorded, never applied.** Accepting one is a release-approver
decision, so a waived record stays blocking and the waiver surfaces in the
report. Six categories — Encryption, Signing, Recovery, Privacy, Accessibility,
Multi-user — cannot carry a waiver at all; the parser rejects it.

## What changed this phase

Two categories moved from blocking to passing:

- **Build.** Previously there was no committed build evidence. There is now a
  beta image built from a digest-pinned base, with a normalised archive that two
  isolated workspaces reproduced byte-for-byte.
- **Licence.** Previously the highest-priority licence gap in
  `LICENSE_COMPLIANCE_REPORT.md`. The owner decided, and the root `LICENSE`,
  eight per-directory files, 127 SPDX headers and a clean scan followed.

**Signing** moved from absent to explicitly `FAIL`, which is a real improvement:
the row now states that no production key exists rather than leaving the
question open.

## Adversarial coverage

`tests/release/test_evidence_model.py` proves the model rejects: a record naming
a missing artifact, a record whose artifact was substituted after the fact, a
record with no digest, a reference escaping the repository, an expired record, a
record from another commit, and a third-party claim from an unregistered
reviewer. It also proves a waiver does not clear a blocking result, and that a
non-waivable category refuses a waiver outright.
